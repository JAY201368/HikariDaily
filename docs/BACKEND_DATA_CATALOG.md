# 当前后端数据能力清单（按服务主题）

代码与文档核对：2026-10-26（北京时间）。按当前源码整理正式链路能力；真实请求记录按发生日期说明，不将历史抽查或规格计划当作当前全国覆盖、准确率或部署就绪的证明。

目前的结构是：**GFS提供主要逐时天气，CAMS提供空气质量，GeoNames提供地点；ECMWF IFS 9km提供独立的日落方向空间云场，结合SunCalc太阳几何生成正式晚霞机会。网站另以逐时天气生成摄影建议。MET Norway已有适配器，默认身份／共享缓存条件不足时禁用。**

## 2. 晚霞／火烧云机会判断

### 输入从哪里来

| 必要信息 | 实际来源字段 | 用途 |
| --- | --- | --- |
| 日落时间／方位／高度 | 本地SunCalc计算 | 定位实际日落方向，比较日落前后半小时五个时刻 |
| 总云及低／中／高云量 | ECMWF IFS `cloud_cover`、`cloud_cover_low/mid/high`（%） | 本地加日落方向及左右25°的25／75／150／250／400km，共16点；检查云载体与光路遮挡 |
| 本地能见度 | ECMWF IFS `visibility`（m） | 同源通透条件，不从AQI反推 |
| 本地小时降水 | ECMWF IFS `precipitation`（mm） | 对齐下一整点的前一小时累计，限制日落窗口条件 |
| 本地湿度 | ECMWF IFS `relative_humidity_2m`（%） | 保留原始云场字段，不作为缺失能见度的替代 |
| 天气分歧 | GFS总云／降水及既有MET核对 | 只作把握与等级限制，不混合分层云 |

后端输出的是“很低、偏低、一般、较高、很高”五级机会，另有独立的“暂无法判断”。同时返回目标日落时间、原因、限制、来源，以及 `medium`／`low` 的依据置信度。

正式模型为 `ecmwf-spatial-2026-10`：以球面几何判断云层是否能被观察、是否仍能受太阳照射，并检查受光／观察通路的云层遮挡，结合本地能见度与降水。云层代表高度为1.5／5／10km，属于工程近似。可见方向云载体不足、本地低云达到80%或小时降水达到1mm时，最高“偏低”；总云／降水显著分歧或允许旧缓存时最高“一般”。必要空间点、分层云、本地能见度／降水缺失，或源不符合目标、版本、时间及覆盖要求时，返回未知。

这里有三个明确的能力边界：

- **没有百分比概率。** 内部条件分数没有经过发生率校准，不能解释成“80%会出现火烧云”。
- **同一IFS源的完整空间输入。** 不拿GFS／MET不同定义的云层拼补，不在空间源失败时回退旧GFS单点评分。
- **空间范围有明确边界。** 检查实际日落方向前方400km、左右25°；云量不等同云光学厚度，未纳入卫星临近变化、实测云高、气溶胶光学数据、山体或建筑遮挡，也没有独立的朝霞机会评估。

实现依据：[晚霞规则](../src/domain/photography/sunset.ts)、[空间契约](../src/domain/photography/sunset-input.ts)、[ECMWF适配器](../src/server/providers/sunset-ecmwf/index.ts)、[正式来源与缓存边界](data-sources.md#正式晚霞空间云场)。

## 3. 当天天气、云层、风雨与能见度

主要来源为 **Open-Meteo / NOAA GFS / `gfs_seamless`**。当前固定请求 `https://api.open-meteo.com/v1/forecast`，不是 Open-Meteo 自动挑选任意天气模型。

| 数据 | GFS 上游字段 | 后端字段 | 单位 |
| --- | --- | --- | --- |
| 2米温度 | `temperature_2m` | `temperature` | °C |
| 2米相对湿度 | `relative_humidity_2m` | `humidity` | % |
| 天气类型 | `weather_code` | `weatherCode` | WMO天气码 |
| 小时降水量 | `precipitation` | `precipitation` | mm |
| 小时降水概率 | `precipitation_probability` | `precipitationProbability` | % |
| 10米平均风速 | `wind_speed_10m` | `windSpeed` | m/s |
| 小时最大阵风 | `wind_gusts_10m` | `windGust` | m/s |
| 10米风向 | `wind_direction_10m` | `windFrom` | °，来向，北0°顺时针 |
| 总云量 | `cloud_cover` | `cloudTotal` | % |
| 低云量 | `cloud_cover_low` | `cloudLow` | % |
| 中云量 | `cloud_cover_mid` | `cloudMid` | % |
| 高云量 | `cloud_cover_high` | `cloudHigh` | % |
| 能见度 | `visibility` | `visibility` | m |

这13项都是模型预报数据；时间已经过去也不会变成站点实况。源元数据标注 GFS 全球约0.11°–0.25°网格，选择某个区县并不等于获取该区县的现场测量。

产品返回北京时间当天00–23时的24个连续小时格。温湿风云及能见度按小时起点读取；GFS 降水、概率和阵风是上游时间戳之前一小时的值，适配器取下一整点，将其对齐到本站的小时区间。请求两天只是为了用次日00时补齐当天23–24时，不对外提供两天预报。

普通逐时天气和摄影建议的能见度仍来自GFS；晚霞空间模型另取IFS本地能见度，两者分别保留来源。AQI、PM2.5、PM10与能见度分别读取，缺失时不互相推算。当前未采集气压、露点、UV、辐射通量、独立降雪量等其他上游可能提供的字段。

实现依据：[GFS 字段表](../src/server/providers/open-meteo/index.ts)、[小时对齐与校验](../src/server/providers/shared/open-meteo.ts)。

## 4. 备用天气与多源交叉核对

备用来源是 **MET Norway Locationforecast 2.0 complete / ECMWF global（MET后处理）**，固定端点 `https://api.met.no/weatherapi/locationforecast/2.0/complete`。

| 已适配的数据 | MET 上游字段或位置 | 当前使用方式 |
| --- | --- | --- |
| 温度、湿度 | `instant.details.air_temperature`、`relative_humidity` | 主源缺失时可回退 |
| 平均风速、风向 | `instant.details.wind_speed`、`wind_from_direction` | 主源缺失时可回退 |
| 总云量 | `instant.details.cloud_area_fraction` | 主源缺失时可回退 |
| 低／中／高云量 | `cloud_area_fraction_low`、`medium`、`high` | 独立保留，不补入GFS主分层云 |
| 下一小时降水量 | `next_1_hours.details.precipitation_amount` | 主源缺失时可回退；没有小时量时不拆6小时累计 |
| 天气类型 | `next_1_hours.summary.symbol_code` | 近似映射WMO分类；未知或不等价类型保留缺失 |

当前适配器没有提供 MET 阵风、降水概率、能见度或空气质量。源元数据说明全球约9 km，部分时段6小时；最终仍逐格匹配，不能把稀疏时段当作完整24小时覆盖。

可用时，温度差≥5°C、平均风差≥4 m/s、总云差≥30个百分点，或一源降水≥1 mm而另一源≤0.1 mm，会记录显著分歧。合并保留主值、备用值及说明，不取平均。各源的危险天气独立判断，备用源的风险不会被主源正常值覆盖。

**实际接通状态：** 最近 T11 六地及 V02 上海验收均记录 MET 为 `disabled`。启用既需要真实可联系的 `MET_NO_USER_AGENT`，也需要满足配置门禁并可用的共享缓存，以遵守缓存头及条件请求。默认共享缓存关闭，因此即便填写了身份，也不代表 MET 已能请求。

实现依据：[MET 适配器](../src/server/providers/met-norway/index.ts)、[归一化规则](../src/domain/normalization/index.ts)、[源加载器](../src/server/source-loader/loader.ts)、[配置说明](DEVELOPMENT.md#服务端来源配置)。

## 5. 空气质量与污染物

来源为 **Open-Meteo / Copernicus CAMS Global Atmospheric Composition Forecasts / `cams_global`**，固定端点 `https://air-quality-api.open-meteo.com/v1/air-quality`。

| 数据 | 上游字段 | 后端字段 | 含义 |
| --- | --- | --- | --- |
| PM2.5 | `pm2_5` | `pm25` | μg/m³，模型预测浓度 |
| PM10 | `pm10` | `pm10` | μg/m³，模型预测浓度 |
| 参考AQI | `us_aqi` | `referenceAqi` | 美国EPA／`US_EPA`口径指数 |

CAMS Global 标注约45 km网格、原生3小时，API小时序列含插值。本站虽然输出24格，也不能称为24次本地站点观测。参考AQI不是中国官方AQI；后端不以单小时PM值另算中国AQI，也不从AQI反推污染物浓度。

目前仅请求这3个字段，没有接入国内监测站实况、臭氧、二氧化氮、二氧化硫、一氧化碳、花粉或沙尘专门指标。CAMS 与 GFS 虽都通过 Open-Meteo 获取，但前者是空气模型、后者是天气模型，不能算作两套天气预报相互印证。

实现依据：[空气质量适配器](../src/server/providers/air-quality/index.ts)。

## 6. 太阳时段与光照条件

这部分由服务器使用 **SunCalc 1.9.0 本地计算**，没有调用独立天文API。输入为 GeoNames 解析的地点经纬度与北京时间当天日期。

| 主题 | 输出 | 当前计算口径 |
| --- | --- | --- |
| 日出、日落 | 具体事件时间 | SunCalc对应太阳事件 |
| 早晚蓝调 | 起止区间 | 太阳高度−6°至−4° |
| 早晚金调 | 起止区间 | 太阳高度−4°至+6° |
| 太阳位置 | 高度、方位 | 高度相对地平线；方位北0°顺时针 |
| 小时光照 | 阶段、直射／漫射／变化光线、解释与依据 | 小时中点太阳位置 + 所属小时总云量 |

太阳在地平线上且云量≤25%时倾向直射，云量≥75%时倾向漫射，中间为变化光线；直射且太阳高度>30°时提示较强反差。总云优先GFS，必要时可用MET兼容回退。

太阳时段计算与天气独立：云厚不会让日出事件消失，但会改变实际可见光效。计算不包含山体、建筑或现场遮挡；观察者高度取0。当前没有接入月相、月出月落、银河、照度lux或曝光EV。天气和空气全不可用时，简报仍可保留太阳计算结果。

实现依据：[太阳计算](../src/domain/solar/index.ts)、[光照规则](../src/domain/photography/light.ts)。

## 7. 拍摄时段、三题材建议与风险

这些内容由已有数据在本站生成，不是另一个外部数据源。规则版本为 `photo-rules-v0.3`，中文内容采用确定性规则和本地模板。当前规则见[规格第6节](../spec.md#6-摄影计算与内容生成)；历史[V10验证](archive/development-2026-10-26/verification/V10-interpretation.md)仅对应当时版本，不能证明当前晚霞模型的通过状态。

| 主题 | 主要依据 | 能得到的内容 |
| --- | --- | --- |
| 风光 | 太阳阶段、总云、能见度、风雨与天气类型 | 黄金/蓝调时刻与远景机会、雾感方向、拍摄时间和要注意的事 |
| 人像 | 太阳阶段、总云、风雨与天气类型 | 柔光／低角度光的时机、户外限制、替代方向 |
| 街拍 | 太阳阶段、总云、风雨与天气类型 | 反差／变化光线、天气氛围与条件性反光机会 |
| 胶片风格 | 题材与光照分析、本地内容表 | 彩色负片、黑白负片或彩色反转片，以及低／中／较高感倾向 |
| 天气概览 | 同一份逐时数据、风险与题材时段 | 一句话概览、温度范围及覆盖情况、变化、机会与限制 |

每题材保留全天时段记录供回看，另选最多3个尚未结束的推荐。缺少必要天气输入时不生成确定排名；风光额外要求能见度。时段按小时、蓝调／黄金时刻边界和太阳几何高度0的过零点划分；过零点采用有界求根，时间包围区间≤1秒，与日出／日落事件分开。合并后最长2小时，当前推荐剩余须至少15分钟，内部评分至少50且光线分量L≥1。天气仍使用所属小时的预报，没有分钟级天气插值。

风况分量取平均风与已知原始阵风的较差值；阵风≤7.9／≤10.7／其余分别给2／1／0，缺阵风不补值。原始阵风>10.7m/s、冻雨码56／57／66／67或L0不进主推荐，对应条件记录仍保留，资格差异不得在合并中消失。冻雨D0，即使雨量0也提示结冰停拍；不新增正式风险码，也不扩大为所有D0／W0禁入。阵风7.9／10.7是工程初值，与四舍五入后显示的风级并非严格等价。

人像／街拍的黄金时刻加分要求几何高度≥0，风光保留日落后余晖。仅白天漫射且总云≥90%的风光L0；其他题材仍按自身条件判断，全局结论不会只因风光一项而统一降级。内部评分分量和推荐资格不进入公开RecommendedWindow，schema仍为v2。

风险规则先检查所有可用源：雷暴码95／96／97／99、小时雨量≥5 mm、平均风或已知阵风≥17.2 m/s，会排除对应常规户外时段；CAMS参考AQI≥151提示户外活动限制。它们是本站筛选规则，当前没有接入官方预警发布流。

实现依据：[摄影分析入口](../src/domain/photography/index.ts)、[时段规则](../src/domain/photography/windows.ts)、[风险规则](../src/domain/photography/risks.ts)、[中文建议](../src/content/advice.ts)、[概览模板](../src/content/summary.ts)。

## 7a. 解释层（`interpretation`，schema v2）

同一份小时数据、太阳事件、风险和三题材建议，再由 [解释层](../src/content/interpret/index.ts) 翻译成白话，随 Briefing 一起返回，报纸和以后的微信摘要直接复用。它不新增数据来源，也不改评分。

| 字段 | 内容 |
| --- | --- |
| `tone`、`headline`、`lead` | 全天结论、≤28 字标题及导语；风险和冻雨优先，缺字段说明排不出时间，空气质量与能见度分开 |
| `weatherLine`、`periods` | 按太阳事件切出的天亮前…入夜六段，每段天色、气温、一句话；段内危险不被多数稀释，缺雨量不据少数小时断言全天雨雪 |
| `nextUp`、`risks` | 以现在为准的 1–3 条要点；连续风险小时合并为一条，已过的标"已经过去" |
| `hours[24]` | 每小时天色、雨、风（国标风级）、远景、空气（美国标准 AQI 档）、光线、气温的 `{label, detail, key}`；风与光线另有器材小字 `short` |
| `hours[].sun` | 八方位与太阳高度的白话读数；日出前/日落后按所选小时的北京时间区分，缺位置时说明原因 |
| `hours[].devices` | 四种器材各自的相关字段、含义、缺失/旧数据/分歧提示、参考释义与走势读数；全由纯函数生成，原始来源ID收在出处 |
| `hours[].sentences` | 每小时 2–3 句：天气和气温、拍摄影响、风险或题材；湿雨小时优先雨情，雪另写防滑保暖；最佳段只覆盖部分小时时写实际交集时刻 |
| `hours[].marks` | 按显式当前时间区分已过／现在／随后；好时段来自已有非D0题材推荐的正长度重叠，并抑制达到小雨档的普通湿雨小时标记；微量雨与雪保持各自分档。风险短语翻译已有代码，表格只渲染标记，不重新评分 |
| `genres`、`sunset`、`dataNote` | 三题材一句话、统一五级晚霞标题与理由、缺字段说明；日落后改为条件回看，夜间行动和胶片适应夜间光线 |

旧`docs/INTERPRETATION_RULES.md`已确认废弃，历史副本不作为现行规则。V10合成样例和DOM检查证明实现一致性，未新增真实上游或天气准确率验证。

## 8. 地点信息

地点来源为 **Open-Meteo Geocoding / GeoNames**，使用固定 `/v1/search` 与 `/v1/get`。后端取得地点ID、名称、行政路径及经纬度，归一为城市或区县粒度，输出时区统一为 `Asia/Shanghai`。

公开搜索每次最多10项，输入去空白后2–40个字符；服务端只接受支持的大陆行政与地点类别。查不到区县时由用户选择所属城市，不自动猜测坐标。它不是地图导航、机位数据库或天气站列表。

实现依据：[地点服务](../src/server/providers/geocoding/index.ts)、[地点过滤与映射](../src/server/providers/geocoding/adapter.ts)。

### 统一数据规则

| 项目 | 当前行为 |
| --- | --- |
| 日期与范围 | 北京时间当天24格；不开放任意日期、多日或任意坐标天气查询 |
| 更新 | 地点缓存24小时；天气与空气正常15分钟、晚霞空间源1小时重验证；晚霞失败冷却15分钟，遵守上游更长等待要求 |
| 来源时间 | 保存获取时间、可用时的发布时间和有效范围；GFS／CAMS／IFS当前适配的发布时间为null，MET可读取`meta.updated_at` |
| 失败后旧数据 | 仅使用获取年龄≤3小时且覆盖目标时段的旧快照，标记stale；超限转缺失 |
| 缺字段 | 保持null及原因，不用0、邻小时或人工样例补齐 |
| 单源失败 | 保留其他可用信息；可能返回partial或stale |
| 天气与空气全无值 | 返回503及unavailable简报，可保留太阳信息 |
| 人工数据 | 仅非生产显式fixture模式；live失败不自动切换人工数据 |

对浏览器只开放两个同源接口：`GET /api/locations?q=…`搜索地点，`GET /api/briefing?place=geonames:…`取得当天整份简报。后者一次包含逐时天气／空气／光照／风险、太阳事件、晚霞机会、三题材建议、摘要和来源信息；没有独立火烧云API。所有外部气象请求在服务端固定适配器内完成。

当前核心链路已接入页面，但 T12 发布准备尚未完成。Open-Meteo免费托管接口仅限非商业用途，晚霞16点按16个地点计量；免费用途与额度、MET身份、真实共享缓存及部署访问的核验状态，见[开发说明](DEVELOPMENT.md)与[详细来源及适配边界](data-sources.md)。微信身份、订阅存储、发送和定时投递仍属第二阶段，没有实际数据服务接通。
