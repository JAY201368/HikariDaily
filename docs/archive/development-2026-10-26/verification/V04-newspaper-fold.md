# V04 报纸首屏与连续双折修复

2026-10-23。用户提供截图，指出首屏报纸超出视口、向下滚动后整张离场再突然出现，以及折叠质感不足。按用户要求由主会话先直接定位和修改运行代码，完成浏览器复验后回填本文；只读 explorer 审查折轴、背面及生命周期，没有派发实施 worker，没有先改任务卡。

## 问题边界与根因

本次仅涉及当前 `src/components/prototype-frontend/` 的展示映射和原生动作、全局展示样式及对应测试。旧前端归档、`prototype/`、服务端、领域计算、数据接口、环境配置和依赖均不变，未启动 T12。

- 完整摘要中的地点、日期、温度及逐时数值又出现在大标题中，窄天气栏还重复首条长变化记录。自然高度超过原型短文案，并触发桌面 `flow-paper`。
- 正文按自然文档底部隐藏，桌面折面却等待另一条 `.14` 进度阈值；手机首次接入时第一折已接近结束。两条时钟和不同坐标系产生空档与跳变。
- 折面使用 `getBoundingClientRect()` 的已缩放尺寸重新建纸，混入舞台缩放；慢图片触发 load 重建时还会继承正文的隐藏样式。
- 两折线性角度、折后偏侧的重心、背面接触阴影缺失以及动作开始时整行换层级，削弱了连续感。跨断点重排保留旧滚动像素，也会从第一折跳到对袋口阶段。

## 实际修正

- 报头保留地点日期，天气栏保留温度覆盖与当前参考小时的降水/风；大标题只去除这些已重复的信息。完整原摘要、全天变化、限制和警告通过报纸上的详情入口读取，并加入无脚本 SSR 内容。具体风险仍在标题下直接展示；没有按字数裁切文本。
- 桌面按未变换的纸张实高和可用视口计算位置/适度缩放，风险长地名样例在 1920×958、1440×1000、1366×900 均完整入屏。四栏保留，略增加天气栏宽度容纳正式文案。
- 手机及异常超长正文保留自然阅读，末屏有原生 sticky 阅读停留。正文与折面在同一 `journey.offsetTop` 交接，换算相同屏幕位置/尺寸；副本接入时两个折角均为零。反向越过交接点恢复同一正文。
- 折面取 offset 布局尺寸，显式恢复副本可见性。两条折轴分开缓动和停顿，移动跟随剩余纸面中心；手机先收拢到可见区域，两折完成后再横置对准袋口。空白纸背、角度相关局部阴影、独立下放及袋口前景遮挡保留，阴影在平面端点归零。
- 窗口改变时保留报纸阅读比例或动作进度，避免窄宽切换直接跳阶段。导航返回日报定位到首屏；详情 Escape 还焦、静态和减少动效继续可用。

## 验证中发现并纠正的问题

- 第一轮单元检查暴露精简标题后 SSR 原摘要缺失；加入无脚本完整概览，保留原契约断言后通过。一次新增浏览器断言的元素类型导致 typecheck 失败，补明确 HTMLElement 类型。
- 第一轮浏览器 43/45：较矮桌面风险样例触发过早的长文模式，手机详情还焦时越过交接点。调整适配门限，并增加末屏阅读停留。
- 阅读停留初版用 padding，sticky 的可用内容区不足，交接几何检查发现约半屏偏差；改为真实 min-height，目标回归 9/9 后通过。
- 只读复核复现慢图片 load 后副本继承隐藏、跨断点跳阶段，并指出新增背面阴影未在端点归零；补可见性、进度重映射及阴影归零，再复跑完整套件。
- 最后一次复验曾被另一个 3110 服务占用 `.next-e2e` 目录锁而未启动。未终止来源不明的服务；其自行退出后重新运行，最终 45/45。用户既有 3000 服务未停止。
