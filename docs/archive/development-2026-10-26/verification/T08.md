## 范围与实现

- 新增 `src/components/briefing-client/{controller.ts,index.tsx,hour-strip.tsx,interactive.module.css}`。独立控制器管理整份简报、请求代次、AbortController、URL／可选本地记忆、可注入 clock／timer／visibility／fetch。React 页面只订阅状态；没有引入摄影规则或客户端上游请求。
- `src/app/page.tsx` 仍直接调用 `getBriefing`，将同一 SSR `BriefingResult` 交给客户端初始化；无地点不默认城市。`src/components/briefing/index.tsx` 仅增加小时／题材回调入口及来源说明；未移植物件动画。
- 搜索去首尾空白、两字起查、300ms 防抖、最多40字；搜索变更即撤销旧查询，校验 JSON 后显示行政路径及城市／区县级别。无结果引导所属城市；React 渲染用户输入。
- 地点／题材写入同页 history URL，URL 字段优先于可选 localStorage（`hikari-daily.preferences.v1`）；非法题材默认风光。JSON 损坏／权限／容量异常不阻断操作。浏览器前后进按 URL 同步地点／题材。
- 切地点取消旧请求、增加代次、清空整份旧简报与小时；即使 transport 忽略 abort，迟到响应也不能安装。小时初始未选，00–23按钮／箭头／Home／End／前后小时只选择同一份简报的小时；题材只显示已生成建议。概览、全天建议及日落机会不因选时重算。
- 首次 SSR 不重复调用 API。前台在上次检查后15分钟或更早的北京时间午夜检查；隐藏时清定时器，恢复时检查日期／age。跨日清整份旧结果及小时，隐藏中跨午夜才完成的请求不启动新请求，待恢复检查。手动重试只有现有 `/api/briefing?place=`，无 bypass／date／coords。
- 同日刷新保留的整份旧结果明确标为“上次完整简报”；不同地点／日期清空。响应必须通过公开 schema、HTTP 状态／信封、地点与日期一致性校验；断网／坏 JSON 归为稳定 `BRIEFING_UNAVAILABLE`，不暴露异常。503 的 unavailable 简报可保留星历与 null 指标。
- 普通文档仍按概览、小时、太阳、晚霞、手册、来源顺序呈现；初始小时未选，三题材按钮显示当前题材。来源区显式区分模型预报／天文计算／规则推断，保留 US_EPA、CAMS约45km／原生3小时／含插值、非中国官方AQI及非区县实测。小时太阳角度仍明确参考 :30。
