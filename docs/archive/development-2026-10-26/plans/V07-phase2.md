# V07 第二阶段：器材页、24 小时明细与手册的白话化

2026-10-24。第一阶段（提交 `0e71994`）已经完成并经用户认可，内容包括：解释层 `Briefing.interpretation`（schema v2）、全站生成文字改写，以及报纸重排。本文列出第二阶段的每一项具体行动和动机，供逐项实施和验收。

## 总目标与约束

**目标。** 报纸之后的三屏（随身器材、24 小时明细、外拍手册）还在给读者看原始数字、来源 ID 和内部状态词。这和第一阶段建立的读法断开了：读者在报纸上读到"3 级风"，翻到器材却看到"平均风 4.26 m/s"。第二阶段的目标是让这三屏也只说"这意味着什么"，技术细节统一收进"数据与出处"。

**约束（与第一阶段相同）：**

- `photo-rules-v0.1` 的阈值、评分、合并逻辑和 `reasonCodes` 都不动。数据获取、API、依赖、服务端也不动。
- 不新增解释逻辑到前端。前端需要的白话都由 `src/content/interpret/` 产出；缺什么就在解释层补纯函数，并配单测。理由：微信摘要以后要复用同一份文字，前端自己拼的文字无法复用，也测不到。
- 保留 `runtime.ts` 依赖的钩子：
  - `data-device`、`data-detail="hours"`、`.selected-time`；
  - 表盘 `#hour-dial` 的 slider 语义；
  - `.reading-index` 的 `aria-live`。
- 保留入包和翻书动画；桌面布局尺寸不变。
- 用户可见文字不得出现禁用词：窗口、本版、模型提示、US_EPA、依据置信度、暂无数据、不适用、漫射、金调、主推荐。唯一例外是"数据与出处"弹窗。
- `prototype/`、`temp/refs/` 不动。

## 一、器材屏幕：一个主读数 + 一句含义

**现状。** 器材屏幕的取值来自 `src/components/prototype-frontend/template.ts:15-18` 的 `data-value` 位，由 `adapter.ts:21` 的 `readings()` 填入：

- **风温湿仪**：标题"平均风 · m/s"，大字是原始风速 `4.26`，阵风也写成 m/s。
- **太阳方位仪**：方位、高度都是度数，表盘上还写着"计算太阳"。
- **测光表**：`readings()` 内部映射为"可能直射 / 可能漫射 / 变化光"和"蓝调 / 金调 / 日间"，底部小字是"预报光照解释"。
- **气象记录卡**：六格原始值（总云量 %、小时降水 mm、能见度 km、参考 AQI、PM2.5、PM10），底部 `card-source` 写着"模型预报 · US_EPA / CAMS"（`runtime.ts:125`）。

**动机。**

- 器材是读者翻过报纸后看到的第一块"仪表"。这里的数字和黑话最集中，也和报纸上的说法对不上。
- "漫射""金调"正是第一阶段明确要去掉的词。
- 记录卡的 AQI 和能见度并排摆放，读者容易把两者互推，而规格要求两者独立。

**行动。**

1. **方位描述。** 在解释层 `levels.ts` 新增 `sunPositionReading(light: LightAssessment): Reading`，按以下规则输出，并配单测：
   - 方位用已有的 `bearingName()` 转八方位中文。
   - 太阳高度 ≥ 0 时写"离地平线 28°"。
   - 太阳高度在 −6° 到 0° 之间时写"刚落山，天还亮"或"快日出了"，依据是这一小时位于正午之前还是之后。
   - 太阳高度低于 −6° 时写"已落山"或"还没出来"。
   - 方位缺失时写"太阳位置算不出来"。
   - 输出例："西北 · 已落山"、"东南 · 离地平线 28°"。
   - 把结果并入 `hourReadings()` 的 `sun` 字段，`InterpretationSchema.hours` 同步加 `sun: ReadingSchema`。schema 版本仍为 `"2"`，因为 v2 尚未对外发布，只在本分支。
2. **风温湿仪。** 把 `template.ts:15` 的 LCD 改为三行：
   - 小标题"风"；
   - 大字 `wind.label`，例如"东风 3 级"或"几乎无风"；
   - 小字一行，例如"阵风 5 级 · 20°C · 湿度 96%"。
   - 阵风缺失时省略，不用平均风顶替，与第一阶段的规则一致。
   - 阵风级数从 `windReading` 现有逻辑中拆出一个 `gustLabel`，或者在解释层另给 `wind.short` 字段，二选一，实现时取改动更小的那个。
3. **太阳方位仪。**
   - 表盘指针逻辑不变（`--sun-angle`）。
   - LCD 改为 `sun.label` 一行；度数移到详情弹窗。
   - 表盘上的"计算太阳"改为"太阳"。
4. **测光表。**
   - 大字用 `light.label`（柔光、硬光、忽明忽暗、黄金时刻、蓝调时刻、天黑）。
   - 小字用 `light.detail` 的第一句。
   - 删除"预报光照解释"。
5. **气象记录卡。**
   - 改为四行：天色 `sky.label`、雨 `rain.label`、远景 `visibility.label`、空气 `air.label`（后附"美国标准"）。
   - 删除 PM2.5 和 PM10 两格，移入记录卡详情弹窗。
   - `card-source` 改为"预报 · {生成时间}"。
6. **`readings()` 的去留。** 把 `readings()` 改为只返回器材需要的白话字段，或者让 `runtime.ts` 的 `renderReadings()` 直接读 `briefing.interpretation.hours[hour]`。
   - 推荐后者，并删除 `readings()` 里的光线和阶段映射表。
   - 如果 `readings()` 仍被单测或 noscript 使用，保留它的数字字段，但不再含"漫射 / 金调 / 日间"。
7. **屏幕尺寸。** 器材 LCD 的字号和行数以现有 CSS 为上限。长标签（如"对敏感人群不健康"）在记录卡里允许换行，不允许溢出器材图片。要在桌面和手机截图里逐个核对。

**涉及文件：**

- `src/content/interpret/levels.ts`、`src/domain/schemas/index.ts`
- `src/components/prototype-frontend/template.ts`、`runtime.ts:120-135`、`adapter.ts:21-24`
- `src/app/globals.css`（器材 LCD 部分）

**验收：**

- 上海、乌鲁木齐两地，在白天、日落前后、夜里三个小时，器材屏幕上都看不到 m/s、°（除太阳高度句）、μg/m³、US_EPA。
- 拨表盘换小时，四件器材同步更新。

## 二、表盘下的读数区：从五行数字改成这一小时的两三句话

**现状。** `runtime.ts:126-130` 往 `.reading-index` 写入五段：

- `#weather-index`：气温、湿度、风 m/s、阵风 m/s；
- `#condition-index`：云量、雨量、能见度 km、"参考 AQI（US_EPA / CAMS）"、PM2.5/PM10；
- `#solar-index`："计算太阳 HH:30：方位° / 高度°。北0°顺时针。"；
- `#light-index`；
- `#hour-note`。

它带有 `aria-live`，读屏会在每次拨针时把这五段数字全部念一遍。

**动机。**

- 这是器材页唯一的成段文字，现在却是一串字段拼接。
- 读屏每拨一小时都要听一长串数字，体验很差。

**行动。**

1. 解释层新增 `hourSentence(readings: HourReadings, hour: Hour, risks): string[]`，输出 2–3 句：
   - 第一句：天色、雨和气温，例如"小雨，20°C，体感湿冷"。
   - 第二句：拍摄影响，取风、远景和光线里最值得说的一项，例如"3 级风，发丝会乱；远处 4 公里开始发灰"。
   - 第三句：只在这一小时有风险或位于最值得拍的时间里时出现，例如"这一小时雨势较大，别安排户外拍摄"或"这是今天最值得拍风光的时间"。
   - 结果放进 `interpretation.hours[h].sentences`。
2. `.reading-index` 改为一个 `<p>` 列表，每句一个 `<p>`。保留 `#weather-index` 作为第一句的 id，这样 e2e 有稳定钩子。删除 `#condition-index`、`#solar-index`、`#light-index`；`#hour-note` 并入第三句。
3. `aria-valuetext` 由"HH:00，北京时间，{state}"改为"HH 时，{sky.label}，{light.label}"。原因：读屏用户拨针时最需要的是这一小时的结论，"数据可用"这类状态对他们没有帮助。
4. `#state-note`：
   - 当 `briefing.state` 为 `ready` 时隐藏。
   - 其他状态时改为读 `interpretation.dataNote`。
   - 原因：第一阶段已规定"数据不足只说一处、说清缺什么"；而 `states` 映射里的"部分数据可用"正是被点名的写法。
5. 场景标题 `template.ts:12` 中的"模型预报 / :30 太阳计算"改为"这一小时的天气和光线"，"点一件器材，读懂一个条件"保留。

**涉及文件：** `src/content/interpret/`、`src/domain/schemas/index.ts`、`runtime.ts`、`template.ts`。

**验收：**

- 拨针后读数区只有 2–3 句白话。
- e2e 断言改为第一句含该小时的天色或气温。
- 禁用词扫描覆盖读数区。

## 三、器材详情弹窗：只放相关项，按"读数 → 含义 → 一天的走势 → 来源"排

**现状。** `adapter.ts:41` 中，点任何一件器材都打开同一个 `hourHtml()`，内容是这一小时的全部 16 个字段，每项都是 `field()` 的输出"值 · 有效 · 来源 open-meteo-gfs"。方位仪和测光表还附上整张 `solarHtml`。结尾固定一句"读数来自所选小时的简报。"。标题是"叶轮式风温湿仪""计算太阳方位仪""经典测光表 · 光照解释""袋内气象记录卡"。

**动机。**

- 点风温湿仪的人想知道风对拍摄有什么影响，而不是看 PM10。
- 每行都挂来源 ID，把真正的含义淹没了。
- 标题里"叶轮式""袋内"是道具描写，不帮助理解。

**行动。**

1. 新增 `deviceHtml(b, kind, hour)` 取代 `adapter.ts:41` 的兜底分支。四种器材共用以下结构：
   - `<h2>`：风、太阳位置、光线、天色与空气。
   - **读数**：大字主读数加 `detail`。
   - **这意味着什么**：1–2 句拍摄含义，取自对应 `Reading.detail`；必要时由解释层补充。
   - **今天的走势**：一条 24 格小条图，CSS grid，与报纸时间轴同一套样式类。当前小时有指针。每格带 `title` 或可读文字，不只靠颜色。
   - **一行来源**：例如"天气为预报，生成于 21:51 · 详细出处见「数据与出处」"。这一行是可点击的 `data-detail="sources"` 按钮。
2. 四种器材各放的内容：
   - **风**：风级（大字）、阵风级、风向（"东北风"，来自 `bearingName(windFrom)`）、气温、湿度。小条图画风级。底部附一行风级对照："3 级发丝乱 / 4 级脚架抖 / 5 级起要压重"。
   - **太阳位置**：`sun.label`、方位度数和高度度数（这里允许出现度数，因为用户点进来就是要看精确值），以及当天日出、日落、黄金时刻和蓝调时刻的起止。光线时刻沿用 `solarHtml` 的白话版。小条图画太阳高度（地平线上下两色）。
   - **光线**：光线类型、云量分层（低 / 中 / 高云，写成"低云很多、高云少"这类话，并附百分比）。附柔光、硬光、忽明忽暗各一句释义。小条图画光线类型。
   - **天色与空气**：天色、雨（档位 + 毫米/小时 + 降水概率）、能见度（档位 + 公里）、空气（档位 + "美国标准 AQI 73" + PM2.5/PM10）。固定一句"空气质量和能见度是两回事，空气差不等于看不远。"。小条图画天色。
3. 数据异常用白话提示，放在"读数"下面：
   - `conflict`："两家预报对这一项说法不一，参考价值打折（一家说 1°C，另一家说 8°C）"。
   - `stale`："这一项用的是早些时候存下的数据"。
   - `missing`：用 `Reading` 已有的缺失文案，例如"这一小时没有能见度预报，远处清不清楚要到现场看"。
4. 删除结尾的"读数来自所选小时的简报。"。标题改为上面四个短标题。弹窗顶栏"逐光 · 读数说明"保留。

**涉及文件：** `adapter.ts`（新增 `deviceHtml`、小条图函数）、`globals.css`（`.detail-strip` 复用时间轴样式）、`src/content/interpret/levels.ts`（云层分层白话、风向）。

**验收：**

- 四个弹窗都只含本器材相关项。
- 非 sources 视图中不出现 `open-meteo`、`US_EPA`、`有效 ·`、`暂无数据`。
- 键盘打开和关闭后，焦点回到器材按钮（e2e 现有断言保留）。

## 四、24 小时明细：从 24 个折叠段落改成一张表

**现状。** `adapter.ts:40` 的 `hours` 视图：

- 标题"24 小时天气与光照"，副标题含 `Asia/Shanghai` 和"小时太阳角度参考:30"；
- 正文是 24 个 `hourHtml()` 折叠段，每段又展开 16 个 `field()`。

读者看不出一天怎么变化，也找不到最值得拍的时间。

**动机。**

- 明细的价值是"一眼看出一天的走势"，折叠段恰好挡住了这一点。
- 时区标识、取样口径属于技术细节，应该放进出处。

**行动。**

1. **表格结构。** 改为一张 `<table>`：
   - 列：时、天色、气温、雨、风、远景、空气、光线；
   - 每格用 `interpretation.hours[h]` 的 `label`，气温写"20°"；
   - `<caption>` 写"今天 24 小时的天气和光线"；
   - 列头用 `<th scope="col">`，时列用 `<th scope="row">`。
2. **行标记。** 不只靠颜色，每种标记都带文字或符号：
   - 当前小时行加 `aria-current="time"`，并显示"现在"标记。
   - 落在任一题材 `recommendedWindows`（排除 D0）内的小时，加"好时段"标记，并写明是哪种题材。
   - 有风险的小时加"⚠"和风险短语。
   - 已经过去的小时整行降低对比度，但仍要满足可读对比度。
3. **小时附注。** 每行附一个"更多"按钮或 `<details>`，展开后是该小时的白话 `detail` 句子。原始字段（值、状态、来源、对比来源）不再出现在这里。
4. **原始字段的去处。** 把完整的逐字段技术表迁到 sources 弹窗末尾，作为一个折叠的"逐小时原始数据"，即现有 `hourHtml()` 和 `field()` 的输出。这样既保留了审计可达性（规格要求缺失、分歧和来源可追溯），又不污染正文。
5. **手机端。** 390px 宽下八列放不下。改为横向滚动容器，首列固定（`position: sticky`），容器带 `tabindex="0"` 和 `aria-label`，以便键盘滚动。不要改成卡片列表，否则又会退回看不出走势的老问题。
6. **副标题。** 改为"{日期} · 北京时间 · 天气为预报，光线为推算"。

**涉及文件：** `adapter.ts`（`detailHtml` 的 hours 分支、`sourcesHtml` 追加原始数据）、`globals.css`（表格与 sticky 首列）。

**验收：**

- 桌面上一屏能看到全表，弹窗内可滚动。
- 手机端可横滑，首列始终可见。
- 现有 e2e"来源分歧 / 对比来源 / 测试缺失能见度"三项断言迁到 sources 弹窗内的原始数据段后仍然通过。

## 五、外拍手册：标签与印刷文字复核

**现状。**

- `adapter.ts:69` 的 `bookHtml` 中，每页的 aria-label 是"{题材}，当天摄影建议"，时间下方的小字是"当天摄影建议"。
- 页眉 `page-running` 显示 `states[b.state]`，例如"部分数据可用"。
- `printedText()` 用 52、44、28 字的上限决定印刷页显示原文还是兜底句。这些上限是按旧文案定的。

**动机。**

- "当天摄影建议"不说明这段时间是什么；第一阶段的词表已定为"最值得拍的时间"。
- 新文案普遍比旧文案长或短，上限没复核过，可能有大量页面落到兜底句"见完整建议"，印刷页就空了。

**行动。**

1. 小字改为"最值得拍的时间"。没有推荐时段时，改用 `interpretation.genres[g].when`（例如"今天已经过去""今天没有好时段"），而不是 `range(null)` 的"暂无数据 / 不适用"。
2. aria-label 改为"{题材}，今天怎么拍"，与详情弹窗 h2 一致。
3. 页眉的状态：`ready` 时不显示；其他状态时显示"数据不全"，详情由报纸和 sources 说明。原因同第二节。
4. 复核上限。写一个临时脚本，不入库，在用完后删除：用 `tests/unit/interpret.test.ts` 的五个场景，加上上海和乌鲁木齐当天实况，统计 `timing`、`light` 等字段的字数分布。
   - 目标：至少 80% 的场景显示原文。
   - 若达不到，优先在 `advice.ts` 里缩短句子，而不是放宽上限，因为印刷页的版面高度是固定的。
   - 调整后补一条单测：五个场景的 `timing` 都 ≤ 52 字。
5. 兜底句文案复核，确保没有"请阅读""详见"这类公文腔。

**涉及文件：** `adapter.ts:61-72`、`src/content/advice.ts`（如需缩句）、`tests/unit/prototype-adapter.test.ts`。

**验收：**

- 五个合成场景和两地实况下，三页印刷文字都显示原文，不显示兜底句。
- 翻页动画和手册锚定不受影响（e2e 现有断言）。

## 六、其余残留措辞

**动机。** 这些都是读者能看到的、第一阶段没覆盖到的位置。它们单独都小，但不改的话，禁用词扫描没法扩展到全页。

**行动：**

1. `adapter.ts:13-15`：`time()` 和 `range()` 的空值返回值"暂无数据""暂无数据 / 不适用"改为"—"。所有可见的空值场景都由调用处给出白话；sources 弹窗内的技术表可以保留"缺失"二字。
